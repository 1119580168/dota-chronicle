# 客户端原包与运行版本

原始压缩包集中保存到归档盘，需要使用的客户端才解压到运行盘。启动器不下载、解压或分发游戏文件；更新史、下载入口、原包库存与运行适配分别记录。

## 三种标注

| 标注       | 判定                                                | 可执行操作                                            |
| ---------- | --------------------------------------------------- | ----------------------------------------------------- |
| 本机可用   | 对应运行目录通过既有构建校验                        | 依适配器提供菜单、比赛和活动；2011 单独标注“仅主菜单” |
| 有可用版本 | 发布者列出下载入口，或本机库存记录了收藏来源 / 原包 | 查看来源、复制下载入口、打开已绑定的归档文件夹        |
| 未收藏     | 尚无上述客户端资源依据                              | 查看历史资料与日期来源                                |

“有可用版本”是资源线索，不表示文件已下载、已通过完整性校验或已经可玩。详情分别显示“原包已归档”“收藏中可下载”“已找到下载入口”和问题包说明。此筛选包括已经本机可用的节点；“本机可用”筛选只显示经过运行目录校验的节点。

不完整原包本身不满足可用资源判定。如果同一编号有另一条发布者下载入口，可以显示“有可用版本”，但保留原包问题。2017 年 build 2311 的收藏文件名虽包含 7.03，仍归到实际构建快照；不会把历史 7.03 首发节点自动变为可用。

0.2.7 新增 7.00 首发构建（2016-12-12 / build 1810）适配器。原收藏的 `not working` 包与 Dota Hub 修复发行包分别归档；只有后者对应的运行目录通过构建校验后，7.00 才显示本机启动入口。私人库存记录留在用户原包库，不随发行包分发。

0.3.8 新增 7.35d 的 2024-04-29 / build 6040 适配器，对应历史补丁日期仍为 2024-03-21。原包留在归档库，使用时只准备完整运行文件；构建身份、容量与实测范围见 [7.35d 客户端适配](client-7.35d.md)。

## 绑定归档文件夹

在“我的版本库”点击“归档文件夹”，选择包含 `archive-index.json` 的原包库。它与客户端运行目录、游廊 VPK 和媒体库分别保存；重新选择归档库不改变游戏绑定。

本机索引为 schema 1，每项包含精确的 `historyId`、版本标签、库内相对 `folder`、`usable`、`collectionClaim`、来源说明和 `files`。文件项包含库内相对 `path` 与预期字节数。分卷必须全部列出；任一卷缺失或长度不同即不显示“原包已归档”。索引登记与游戏内验证是两项独立工作。

索引、归档路径和私人收藏信息存放在用户选择的文件夹与本机配置中，不进入发布包。索引超过大小 / 条目限制、出现越界路径、重复编号或符号链接时拒绝读取，并在版本库显示错误。读取成功不表示重新完成 CRC 或 SHA-256 检查；原有完整性证据应另外保留。

取得新原包后先补充本机索引，保存原名与全部分卷，需要使用时再解压、核验实际构建并绑定客户端。没有现成运行适配器的版本仍需开发与验证；下载入口和索引不能自行授予游戏或影像权限。归档整理不自动删除现有运行客户端。
