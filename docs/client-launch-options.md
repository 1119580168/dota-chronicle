# 客户端语言、音量与控制台

## 选择游戏界面语言

在版本或 RPG 详情的启动按钮上方，选择“游戏界面语言”。每个客户端单独保存设置，下次进入主菜单、普通比赛、RPG 或加入房间时生效。“本地房间”也提供同一版本的语言选择；专服自身无需界面语言，房主加入时采用客户端设置。

默认沿用英语。启动器读取对应客户端的散装本地化文件，以及 `pak01_dir.vpk` 中的语言目录，只显示实际检测到的界面语言。旧配置无需迁移；更换为缺少已选语言的客户端目录后自动回退到英语。

本机 2010 原型和 2011 年 7 月包目前只检测到英语；6.77c 至 7.37e 的其他 16 个已绑定客户端均检测到简体、繁体中文资源。该判断是资源检查，不代表已经逐版、逐语言检查了所有文本。RPG 自身的翻译、英雄语音及未翻译内容取决于原包，选择中文界面不会自动下载中文语音包。

设置保存在本机 `library.json` 的 `launchOptions.<客户端 ID>.language`。守护启动使用经过白名单校验的 `-language` 参数，不接受任意控制台或命令行输入。语言代码依据 [Steamworks 支持的语言](https://partner.steamgames.com/doc/store/localization/languages?l=schinese)，本地资源与实际启动结果仍需逐包核验。

## 7.00 音量偏低的处理

用户确认 7.00 普通比赛基础试玩通过，但声音异常低。其 `game/dota/cfg/machine_convars.vcfg` 保存的主音量为 `0.192144`，音效为 `0.195467`，游戏语音为 `0.199717`，音乐为 `0.196884`。日志确认声音系统已经初始化；主音量与各分组音量同时偏低是本轮发现的明显原因。

退出本程序启动的游戏后，先独立备份原配置，再仅调整该客户端的五个音量值：主音量 70%、音效 80%、游戏语音 80%、音乐 30%、语音聊天 70%。原包和其他设置保留。备份位于客户端上一级的 `audio-backups`；本机详细前后值另存私有记录，不进入 Git 或发行包。

这次修复不是每次启动强制覆盖音量。用户后续在游戏内调整的设置继续保存。声音系统、Windows 应用音量、输出设备和游戏资源是不同层级；若仍偏低，应按实际复测继续检查。

调整后用档案馆保存的简体中文设置再次冷启动 7.00，用户确认中文界面和声音复测通过；退出后核对游戏音量值仍保留，Steam 临时路由与本次配置均恢复。

## 旧客户端控制台与备用热键

通过 0.3.5 档案馆启动的旧客户端统一传入 `-console` 和 `+con_enable 1`；临时 CFG 执行 `con_enable 1`、`bind F8 toggleconsole` 与 `hideconsole`。启动时启用控制台，再隐藏初始面板，用户可按 **F8** 开关。

F8 是备用键，可以与设置页原有的反斜杠 `\` 同时绑定到 `toggleconsole`。这项调整不清空整套按键，也不重置设置页的控制台键；如果设置页仍显示 `\`，不代表额外的 F8 绑定没有生效。

### 7.22 的原生证据与真人复测

7.22 原客户端 `pak01_dir.vpk` 中的本地化字段 `dota_settings_enable_console_tooltip` 明确说明：**启用控制台的设置更改将在下次启动游戏时生效，`-dev` 或 `-console` 启动参数会覆盖该设置。** 证据位于 `resource/localization/dota_english.txt` 与 `resource/localization/dota_schinese.txt`，对应留存包第 22117 / 22114 行。游戏已经运行时勾选该项，应先结束游戏并重新启动，不能仅凭勾选状态判断当前控制台已可用。

用户确认，**调整前 7.22 的 F8 已能打开控制台**，设置页显示的键为 `\`。因此，不能把此前现象归因于缺少 `-console`。新参数冷启动后的实体键盘复测又确认 **F8 可以开关控制台，反斜杠仍无效**；本次保留 F8 作为已验证的备用入口，没有宣称修复了反斜杠。反斜杠无效的具体原因仍未确定。

通用参数与临时配置已通过后端逻辑检查；真人热键复测仅覆盖 **7.22**。自动键盘输入未能可靠触发该游戏的热键，不能据此断言键位失效，也不将自动输入写成真人复测通过。其他客户端的实体键盘开关效果需分别确认。

### 启动参数、配置开关与调试通信

| 项目                                    | 本程序中的作用                                                                     |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| `-console`                              | 在客户端启动阶段启用控制台；7.22 原生提示明确将其列为覆盖设置的参数                |
| `+con_enable 1` / CFG 内 `con_enable 1` | 设置允许激活控制台的变量，与启动阶段参数分别保留                                   |
| `bind F8 toggleconsole`                 | 增加 F8 备用开关，不要求设置页把原控制台键改成 F8                                  |
| CFG 内 `hideconsole`                    | 隐藏初始控制台面板，保留之后用热键打开的能力                                       |
| `-condebug`                             | 保存原生控制台日志，不等于屏幕内控制台或热键已经通过验证                           |
| `-vconsole`                             | 仅用于早期 Source 2 普通本地房主初始化的控制通信分支，不作为普通启动的 F8 开关修复 |

档案馆直接启动选定旧客户端的可执行文件，并将参数传给该进程；不会修改 Steam 中最新版 Dota 2 的启动项。在最新版的 Steam 属性页加入参数，不会自动改变档案馆直接启动的旧进程。

官方站点资料作为补充：[Valve Developer Community 引擎参数说明](https://developer.valvesoftware.com/wiki/CHILLMODEA/Pages/Command_line_options) 区分启动参数与 `+` 控制台命令，[开发控制台说明](https://developer.valvesoftware.com/wiki/De/Developer_console) 提到显式绑定。上述页面是通用引擎资料，不能替代留存 Dota 2 构建的原生提示和实际键盘测试；当前结论优先依据 7.22 原包及用户复测，不套用后续版本的公开问题记录。
