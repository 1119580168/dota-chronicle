# 设计与实现 · 0.3.0

## 产品目标

Dota Chronicle 是完全离线的个人 DOTA 2 档案馆：浏览历史更新，查看真实客户端与 RPG 影像，启动已核验的本机客户端，并准备同版本本地房间。界面重设计覆盖历史时间线、RPG 档案、本地房间、我的版本库四个页面；不更换游戏文件、媒体素材或启动适配器。

## 视觉系统

采用档案阅览台的布局与 DOTA 的克制视觉语言：炭黑内容区、略亮的暖黑详情区、暖白衬线标题、古铜日期与元信息、朱红启动按钮。真实游戏截图与原包 RPG 艺术承担主要视觉表达，界面使用细边框、明确对齐和少量短分隔线，避免霓虹、装饰性渐变和悬浮卡片。

| 用途               | 色值                  |

按作者 CSS 中的实体色计算：暖白对主背景为 15.40:1，次要文字对详情背景为 6.99:1，辅助文字为 5.31:1；主按钮文字 `#FFF2E3` 对默认 / 悬停底色分别为 5.93:1 / 4.61:1。这些数值仅对应上述颜色组合，不包含图片、透明叠层、禁用状态或所有像素，也不等同于全面无障碍认证。

页面标题采用 Noto Serif SC，品牌与详情版本标签采用 Cinzel，版本数字和年份导航采用 Barlow Condensed，正文采用 Noto Sans SC。已有字体和 Lucide 图标随程序离线保存。基准字号为 13px；正文和控制使用 12–13px，辅助信息主要为 11px，页面标题为 29–35px。品牌副标题与非关键版本印记为 10px。关闭字体合成，使用已打包的字重。

## 信息架构

### 历史时间线

历史资料与可运行收藏分开：离线更新索引保留完整历史，客户端适配目录只登记经过核验的构建。按实际更新时间排列；公告、正式更新与本机构建快照分别标注，未核实日期保留月份或年份精度。

中间列表只展示封面、版本、标题、日期、可用状态及简短引擎 / RPG 信息，详细说明进入右侧折叠区。只有确切关联到本机收藏的条目才展示对应影像。无收藏记录采用紧凑的文字行，连续客户端维护更新折叠成组。

筛选分为全部更新、编号与收藏、有可用版本、本机可用、未收藏。后两类与下载入口分开判定；“有可用版本”不表示已安装。“本机可用 · 仅主菜单”保留为独立权限，不能误示为可以比赛。年份导航随列表滚动更新当前年份，窄窗可横向滚动；点击年份使用工具栏实际高度定位。

### RPG 档案

官方 RPG 与已停更游廊分别成组，按活动时期排列。卡片保留真实封面、名称、时期、运行版本、入口状态；完整介绍、验证范围和启动动作放在右侧。宽窗使用三列，小窗使用两列。付费与停更筛选属于地图收藏规则，不由视觉改版重新判定。

### 详情与启动

详情依次展示封面、年份 / 引擎、版本与标题、补充信息和可用状态。版本与标题允许自然换行，避免将长地图名称挤成窄列。界面语言与主启动按钮紧邻，主菜单与本地开服作为次级操作。完整说明、构建校验和资料依据保留在可展开区域，日期和时代影像直接可见。

2011 不完整客户端保留主菜单入口，比赛与联机入口禁用。基础试玩、兼容复原、跨机联机分别标注，不将进入地图等同于完整通关或多人通过。运行中的客户端限制冲突启动；会话状态更新只同步相关控制，不反复替换用户正在输入的搜索框。

### 本地房间与版本库

创建房间优先展示版本、模式、UDP 端口和密码四个字段。语言、监听网卡和虚拟网络兼容设置放入默认折叠的“语言与网络设置”；运行路线与开服按钮置于展开说明之前。页面顶部提供跳转“加入已有房间”，下区填写房主地址并启动连接。

右栏给出可复制的游戏控制台命令及三步连接说明；复制后按钮显示短暂成功反馈。公网说明与验证边界折叠保留。房间草稿在本次界面切换中保留，程序不因界面改版创建公网地址或修改防火墙。

版本库集中提供扫描、绑定、归档目录和本机配置操作。运行目录与压缩包归档分开，选中版本可查看同一份档案详情。未准备或缺失组件保留具体原因。

## 交互与可访问性

- `Ctrl+F` / `Ctrl+K` 聚焦并选中当前页面搜索框。中文输入法组字期间不过滤、不重建输入节点；提交组字后更新结果。
- 搜索框清空按钮与搜索中的 `Esc` 仅清除文字，保留当前筛选。空结果提供明确的恢复全部入口。
- 选择记录保留当前列表滚动位置与展开的维护更新组。同一选项刷新时保留右栏滚动、说明展开状态、焦点及文本选区；切换详情则从顶部阅读新的内容。
- 导航、筛选、记录与年份提供 `aria-current` / `aria-pressed`；图片、图标按钮、搜索和详情面板具有相应标签，反馈使用状态播报区域。
- 常规按钮命中高度至少 36px，主要启动按钮至少 46px。键盘焦点以高对比古铜轮廓标示；禁用状态同时依赖原生权限状态和说明，不仅依靠颜色。
- 页面切换使用短暂淡入，悬停动画克制；`prefers-reduced-motion` 同时关闭 CSS 动画 / 过渡及平滑年份、房间跳转。

这些保留范围针对当前运行中的界面，不承诺跨程序重启保存浏览位置。语言和客户端绑定继续通过原有本机配置机制持久化。

## 真实媒体与离线边界

时间线小封面约 106 × 64px；RPG 卡片封面按原画展示。右栏封面使用完整原图比例，主界面、选人、游戏画面的缩略图使用 16:9 且 `object-fit: contain`，保留 HUD。没有素材时显示可识别的占位，不借用其他构建画面，也不生成替代历史截图。

媒体保存在独立用户目录。渲染端只取得内容 SHA256 与本地协议地址；打开原图和播放动画保留标题及来源。退出全屏继续显示原媒体，关闭播放器暂停并清除视频源。媒体索引、截图、用户目录、绑定、密码和运行日志均不进入公共源码发行。

采用 Electron 与 Windows 自带 PowerShell，渲染进程启用 sandbox / context isolation，关闭 Node integration。UI 只通过受限 preload API 与经过来源核验的 IPC 操作；运行时禁止外部网络请求、CDN、遥测与自动更新。Fullscreen API 仅开放给本启动器主框架。

启动参数继续经过登记模式、端口、密码与地址校验。只管理本程序创建且 PID、路径、创建时间匹配的进程；Steam 路由与 Source 1 活动挂载仍由独立守护进程恢复，关闭界面不能提前结束正在使用的租约。本轮 UI 改版不扩大这些权限。

## 验证与交付范围

当时已完成 30 项后端测试、离线 UI smoke 与 UI experience 回归通过。体验测试覆盖 IME、搜索快捷键与清空语义、选择状态、年份位置、滚动 / 展开 / 焦点恢复、运行状态下的按钮权限及媒体的 Escape / 全屏行为；隔离配置中禁止游戏启动和持久化用户绑定。

真实媒体截图位于被 Git 忽略的 `test-results/layout-final/`，用于时间线、官方 RPG、游廊 RPG、房间与版本库的人工检查。响应式验收尺寸为 1080 × 708、1120 × 780、1440 × 960、1920 × 1080；主按钮首屏、横向溢出和最终截图结论见 [design-qa.md](../design-qa.md)。

最终四尺寸、原生桌面和 0.3.0 发行部署结果见 [design-qa.md](../design-qa.md)。界面回归不替代游戏内试玩、完整通关或跨机多人测试。
