# 旧版技能沙盒：7.22 技术方案与运行验证

检查日期：2026-10-06。状态：**0.3.6 已部署，7.22 技能编辑器的打包程序运行与恢复验收通过**。本轮覆盖图形编辑、风暴之拳、时间锁、冷启动、退出后再次进入试玩、本机名称索引和五文件恢复；入口仅面向 7.22 / build 3504 的本机单人原生英雄试玩，不使用 `-dev`。目录内其他技能、中文 GUI 输入、复杂依赖、音效与多人不由本轮结果推定。

## 目标与当前推荐路线

目标是在历史客户端中添加、删除和调整该版本真实存在的技能，用于组合试玩与发展史录像，效果继续由对应旧引擎执行。

当前路线是**独立原创 Lua 模块、当期 Panorama 面板与原生英雄试玩环境**。旧版引擎继续执行技能，技能定义来自正在运行的 7.22 客户端 KV，名称索引从该构建原 VPK 派生，无须另建地图。只有原生试玩无法承载后续需求时，才考虑完整 addon。

图形编辑器作者源与协议见 [技能编辑器说明](../tools/legacy-ability/SKILL_EDITOR.md)，编译与动态挂载见 [面板加载记录](legacy-skill-editor-ui-loading.md)，档案馆入口见 [项目 README](../README.md)。前期 [最小 Lua 验证模块](../tools/legacy-ability/README.md) 仍独立保留，只允许 `sven_storm_bolt`；不能把它与新编辑器的运行时目录混为一谈。两者都不调用 `Activate`、不覆盖 Valve 入口、原 KV、DLL 或 VPK，也不接受任意 Lua 文本。

| 路线                                               | 当前证据与限制                                                                                     | 决策                             |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------- |
| 原生 `dota_create_ability` / `dota_remove_ability` | 本机四个 64 位原 DLL 的 ASCII 与 UTF-16 检查未发现这两个名称，没有原生注册的运行证据               | 不作为当前可用方案               |

本轮结论限于 **7.22 / build 3504 / Source 2**。其他 Source 2 构建与早期 Source 1 客户端需逐版验证。

## 前期最小 probe 的验证流程

测试者管理唯一命名模块的临时安装与精确清理，不覆盖客户端已有文件。在已经初始化的普通本地比赛中开启测试所需作弊，并按已测入口加载：

```text
sv_cheats 1
script_reload_code chronicle_ability_probe_v1.lua
chronicle_ability_env
chronicle_ability_test ordinary
chronicle_ability_precache
```

`chronicle_ability_test ordinary` 是本轮普通 `dota` 地图的显式授权，只存在于当前 Lua VM。原生 `hero_demo` 已验证，省略该授权命令。将唯一原创文件放入客户端的 `game/dota/scripts/vscripts/`，即可在已初始化的试玩中按文件名加载，无须覆盖 `hero_demo` 原脚本。文件加载本身不创建游戏模式、不调用 `Activate`。

```text
chronicle_ability_target_clear
chronicle_ability_remove sven_storm_bolt
chronicle_ability_list
```

这里共有 10 种 `chronicle_ability_` 命令，重复出现的 list、level 不另计。它们来自独立作者模块，**没有安装进 0.3.5 发行版**。

模块只允许服务端 Lua、非专服、本地 listen host 和满足条件的试玩上下文；其他玩家发起的操作会被拒绝。添加前检查真实英雄、技能定义、重复项与空槽，不覆盖或重排原技能。升级和删除只接受模块自己添加的同一技能句柄，不接受原生技能或任意名称。

施法测试只创建模块自己的隔离目标，使用原生施法指令，再读回魔法值、生命、眩晕和冷却。`CHRONICLE_ABILITY_CAST_ORDER` 只表示指令已发出；成功提示必须结合结果。清理只针对该模块创建的对象，不笼统移除原敌军或同名 modifier。

不要使用 `script_reload` 重启整个试玩入口。模块在全局保存实例，重复执行文件会复用当前实例；建立新的地图 Lua VM 才是重置工具和验证新源码的边界。

## 当前交互与兼容范围

图形编辑器与控制台共用服务端检查，定义来自当期 `npc_abilities.txt`、`npc_heroes.txt`。原包本地化为 UTF-16，直接 Lua 加载失败；后台按本机构建定义从原本地化提取名称，生成临时 UTF-8 索引。中文与英文目录 API 检索已实机读回，中文 GUI 输入未单独验收，不导入最新版名单。读取真实可见槽、隐藏槽和天赋，不照抄固定槽位数量；本轮索引 14 的技能确实显示在 HUD，不能简单把所有索引大于 5 的技能判作不可见。

只能修改工具精确拥有的新增技能。**替换、换序、清空全部技能、修改原技能与恢复原英雄方案未提供**。已有同名技能、满槽及错误等级会被拒绝；异步预载结束后再次核对同一 host、英雄和试玩上下文。添加、升级与删除后读回其他技能状态，不用重写原技能掩盖引擎变化。

公开项目包含原创 Lua、界面作者源、同构建编译的原创面板与精确安装逻辑。Valve 地图、KV、样式依赖与媒体从用户本机对应构建读取，原 `hero_demo` 依赖特殊 C++ 初始化，不复制它的脚本来冒充独立兼容地图。原生试玩不足以承载需求时，再单独验证 addon。

当前 `skills` 入口沿用语言、F8、进程守护和恢复链，仅允许 canonical 7.22 / build 3504；不依赖云端、登录或网页。控制工具连接 127.0.0.1，原生调试监听并非仅回环，仍须随机认证和每条命令前的进程及端口归属核对。多人入口没有开放。

## “任意技能”的边界与剩余验收

目标是操作该版本真实存在的技能定义。添加实体成功，不等于换到任意英雄后效果完整。

- 主技能可能依赖附属按钮、召唤物或原英雄状态；已知依赖需成组管理，未知组合标明未验证。
- 天赋、隐藏项、`generic_hidden` 和引擎必要技能单独管理，不混入未来的普通清空操作。
- 移除后确认被动、持续效果与召唤物是否残留；清理依据技能实例和依赖记录，不删除所有同名 modifier。
- 添加前预载对应资源，再实测声音、粒子和模型；异步预载完成不能替代效果验收。
- Invoker、Morphling、Rubick、Meepo、变身和分身技能建立独立兼容表，单个风暴之拳通过不能推广。
- 缺失 API 或绑定原英雄的 C++ 行为应记录限制，不覆写原技能实现来改变历史效果。

后续逐项验证中文 GUI 输入、声音与资源效果、复杂依赖和同版本多人。冷启动、昆卡退出后再次进入试玩、本机名称索引、五文件恢复及 0.3.6 打包部署均已通过；风暴之拳与时间锁分别取得主动施法和被动效果读回，不能由此把目录中每一项标为兼容。普通地图不带 `-dev` 的技能链可另作对照；当前 0.3.6 入口只开放已验证上下文的原生试玩。
