# 迁移与异常恢复

## 正常升级

1. 在原电脑、原程序目录结束所有游戏和专服，等待会话完成恢复。
2. 完整解压新程序到可写目录，保留全部相邻文件。
3. 将原 `data` 复制到新 EXE 相邻位置，再打开新程序。不要只复制 EXE。
4. 检查“我的版本库”的绑定状态；移动过客户端、地图原包或外置媒体时重新绑定对应路径。

另一台电脑不共用原电脑的运行会话。Steam 使用自己的账户，客户端与地图构建需重新核验；本地房间重新选择实际网卡。没有媒体库也可以浏览档案和启动自己的客户端。

## 待恢复会话已经被搬动

界面会显示恢复原因、原数据位置和操作指引。看到此提示时不要手工删除会话状态、锁或游戏中的临时文件。

- 原电脑与原目录仍在：用原位置的启动器结束会话并完成恢复，再回到当前副本点击“重试恢复”。只有归属、会话和已完成结果能够验证时，当前副本才同步结果。
- 原位置丢失、跨电脑，或旧记录没有本机归属：程序不会自动停止进程、修改注册表或清理原游戏路径。可选择导出新的数据目录保留收藏，旧会话证据继续留存。

导出之后，按照界面给出的路径与步骤退出程序、把旧 `data` 改名备份，再将导出的目录放到 EXE 旁并命名为 `data`，重新启动。开发测试通过 `CHRONICLE_DATA_DIR` 使用独立数据目录时，调整该环境变量指向新目录。

导出不包含会话、客户端锁或租约，也不会恢复原电脑的游戏与 Steam 修改。原电脑的旧客户端必须先通过原位置的恢复流程处理；新电脑重新取得干净客户端，并核对构建。不要分享包含会话或备份的整个数据目录。

存放在原 `data` 内的媒体会复制到新目录的 `media`，随新数据目录一起移动。外置媒体只保留绑定配置，另附 `MEDIA-RECOVERY-INSTRUCTIONS.txt`；迁移后需要重新绑定本机素材目录。损坏的媒体配置会阻止导出，原配置与恢复证据保留；损坏的索引保留原文件，导出后仍需先修复再导入。

## 媒体错误

媒体配置或 `index.json` 出错时，档案馆继续显示时间线与启动入口，媒体区域显示具体错误位置并停止导入。只有索引确实不存在才初始化新库。既有文件无法读取、格式错误或 schema 无效时不会被空库覆盖。

先备份并修复提示文件，再刷新档案馆；素材不会因为本次错误被删除。媒体格式支持 PNG/JPEG 图片和 WebM 视频。

## Windows 脚本策略

普通界面及客户端守护使用程序自带运行时。7.32 专服的启动与“补充 Bot”管理脚本采用只对本次子进程生效的执行策略，仍检查专服 PID、执行路径及创建时间，不调整系统或当前用户的全局策略。企业设备的强制策略可能继续阻止脚本，应按设备管理规则处理。
