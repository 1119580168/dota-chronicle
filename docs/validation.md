## 发现并处理

- 父 PowerShell 7 的模块搜索路径影响 Windows PowerShell 5.1 安全模块加载。后端为 Windows PowerShell 独立设置自带模块路径。
- 本机 SteamPath 指向其他游戏的兼容目录。现在从正在运行的 Steam、安装候选中寻找签名有效的 Valve DLL；不改写该安装路径值。
- Windows Registry Provider 读取的键句柄不能直接写入。设置路由时显式打开当前用户注册表的可写句柄，退出后按原类型与是否存在恢复。
- Source 1 模块确认使用 32 位 PowerShell；64 位 Windows PowerShell 的模块枚举不用于否定 32 位客户端已加载 Steam。

## 验收边界

客户端 / RPG 的既有游戏内容测试由原运行库的真人与原生日志记录提供。本轮重点是新启动器集成、可恢复的生命周期，以及目录版独立运行；没有重新重复全部地图的游戏操作。

两台电脑、两 Steam 账户、虚拟网络或公网连接未验收；官方 RPG 完整通关、所有人数限制和自然胜利结算也未统一验收。2011 缺失 server.dll 继续是档案层面的缺口。当前未使用游戏模拟器、未自动改防火墙、未上传任何源代码或游戏资源。

## 可重复执行

```powershell
npm ci
npm run build
npm test
npm run test:ui
npm run release
```

`test:ui` 使用全新、空的本机配置，不启动游戏，并将 Chromium 网络切为离线；检查四页面、禁用状态、沙箱与外部请求。可设置 `CHRONICLE_TEST_EXE` 为 Windows 目录版完整路径，检查实际发行程序。

本机实际游戏测试的私人进程与日志证据保存在被 Git 忽略的 `test-results`；不随源码发布。
