# 版本标题与历史概述

0.3.3 将客户端档案与编号补丁改为按实际时期、具体内容编写。标题突出时代背景或本次改动，描述补充两三项最有代表性的变化；测试状态、组件指纹与联机验收继续由各自字段说明。

## 文案与时间

- 编号补丁说明该次更新。字母修订只写当次调整，不把所属大版本的新功能写成再次首发。
- 客户端档案说明这份实际保存包能展示的面貌。RPG 可以在后来的包中留存，但留存不代表活动在该补丁首次推出。
- 补丁实装日、预告日与本机快照日期分别保留。2011 只核实到月份，2010 只核实到年份，不补写精确日。
- 2017 年 build 2311 继续使用真实构建编号，不因收藏文件名而变成 7.00 首发或未经核实的小版本。
- 2010 的开发形态和已有包的界面特征依据实际保存素材，明确属于观察记录。

主要纠正包括：6.78b 是 TI3 前保存点，不能等同于正式赛事版本；6.85b 是 Reborn 已上线后的修订；6.83 之后仍有 Source 1 更新；7.19 保留早期合作活动而非同时推出这些活动；7.30e 的 2021 年补丁与 2022 年天地迷宫保存包分开；7.37e 的 2024 年补丁与 2025 年构建分开。

## 维护入口

`resources/editorial/clients.json` 是 18 份客户端标题、短标签与描述的作者源。`patches-early.json`、`patches-middle.json`、`patches-late.json` 分别保存早期、2018–2021 和 2022 年之后的编号补丁文案。每条记录附 `contentSources`，本机观察另附 `contentNote`。

维护期通过 `scripts/editorial.cjs` 应用文案，只写标题、说明和内容来源字段。客户端导入与历史生成都使用同一份作者源。文案不改动版本编号、日期、节点标识、运行绑定、文件指纹、地图、验证状态或开服参数；历史记录仍不能授予运行能力。

编号补丁的正文依据 Valve [官方补丁页面](https://www.dota2.com/patches/) 及对应 patchnotes 数据。早期规则依据 Valve Steam 原始更新公告。原始 API 快照留在 Git 忽略的本机目录，应用只读取预先生成的离线档案。
